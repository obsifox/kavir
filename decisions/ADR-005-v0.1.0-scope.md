# ADR-005: v0.1.0 scope

Status: proposed (one-way-door checkpoint — user decision pending)
Date: 2026-10-26
Question: What exactly does the first published version contain — and refuse
to contain?

Options considered (at least two):

  A. Broad ambitious surface (generics + concurrency + async + package
     registry + rich stdlib) before any release. Evidence against: C-715
     (stdlib freezes carry permanent compat cost), C-701..C-706 (package
     infrastructure is its own project), C-615/C-616 (async adds
     complexity), C-722..C-725 (long pre-1.0 limbo kills projects — Perl 6,
     Crystal, Julia delayed 1.0 until a credible stability promise).
  B. Narrow honest vertical slice, released early as experimental: one
     tier-1 target, small core subset, conformance suite, docs set, hardening
     evidence, honest README with a "Not yet" list (release-0.1.0.md rules).
  C. No public release until parity with an industrial toolchain. Evidence
     against: not credible per feasibility-report section 2; also violates
     the honest-labelling charter.

Trade-offs: A risks never shipping (the W8 lesson). C is not honest. B is
the only option consistent with ADR-001 and the release-0.1.0 milestone map;
its cost is that v0.1.0 is explicitly NOT useful for production work, which
is fine for the declared audience.

Decision and reasoning (RECOMMENDATION to user — not yet final): Option B,
with the concrete cut:

IN v0.1.0 (all four phases of the vertical slice: lexer, parser, checker,
QBE codegen, driver):
- Core subset: functions, structs (value types), enums (sums) + match with
  exhaustiveness, Option/Result, let/mut + ownership/borrow basics, if/while/
  loop/break/continue, integer/float/bool/string-literal types, fixed-width
  numerics with checked overflow in debug mode.
- Modules: single-crate multi-file modules with explicit imports; NO registry,
  NO network fetching (lockfile/reproducibility ADR work comes later).
- Tooling: `kavir` CLI (build/run/check), one formatter pass, test runner
  (kavir test), error messages with file:line:col spans (C-313 lesson).
- Tests: conformance suite from day one (every feature = spec entry + test),
  fuzz targets for lexer/parser, sanitizer builds in CI.
- Docs: English doc set per documentation.md + in-scope Persian pages.
- Tier-1 target: x86_64-linux (the sandbox); arm64-linux as stretch only if
  CI proves it (QBE already supports arm64 — cheap to try, not promised).

OUT of v0.1.0 (the "Not yet" list — honest README):
- Concurrency/threads in the language (single-threaded v0.1.0; ADR-006 later);
- Generics beyond the minimal monomorphizing core (possibly all of them);
- Package manager/registry (local files only);
- Async/await, macros, traits beyond basic bounds, closures if they slip
  schedule (decision recorded at release time);
- Debug-info completeness beyond line tables; any performance claims.

Reversibility (cheap / costly / one-way): the scope cut itself is cheap
(additive later); what is one-way is publishing claims — hence the
release_check.py gate and the README rules.

What result would show this was wrong (experiment or metric): release
checklist from release-0.1.0.md passes but zero external users can run the
tour example from README on a fresh machine (fresh-install test fails) —
then the slice is still too big or too broken; cut again before publishing.

C-715, C-722, C-723, C-724, C-725
