Status per the milestone ladder in ADR-005 v3. M1.1/M1.2 stand as
AUTHOR-APPROVED (not independently verified); independent verification
of commit 28ba9f1 is being performed by a third party. M2 was built on
top of 28ba9f1 per the user's instruction.

## What was built (scope: user-mandated — nothing more)

- `print(expr)` / `print("...")` — output via the write syscall
  (fd 1) in the compiled ELF; byte-identical output in the interpreter.
  No implicit newline, no padding (ADR-008 decision 4).
- Arithmetic `+ - * / %` on i32, executed at RUNTIME (no folding —
  ADR-008 decision 2), truncating division, TRAP per ADR-007 on:
  out-of-range results, division by zero, INT32_MIN / -1,
  INT32_MIN % -1. Trap contract pinned (ADR-008 decision 3):
  one line to fd 2 — `trap: integer overflow at <file>:<line>:<col>`
  or `trap: division by zero at <file>:<line>:<col>` — then
  `exit_group(101)` (exit code pinned; interpreter uses the same code
  and identical bytes).
- `if (expr) { ... } else { ... }` — condition = integer expression,
  nonzero = then-branch (no comparison operators yet — not in the M2
  scope; M3 introduces them).
- Unary minus on integer literals only; the numeral 2147483648 is
  accepted only directly under unary minus and defines INT32_MIN
  (ADR-008 decision 1). `--2147483648` and `-(2147483648)` are
  compile errors.
- Backend: stack slot per vreg, overflow checks via `jo`, explicit
  guards before `idiv`, cold trap-stub pool + shared exit, and an
  emitted freestanding runtime function `kavirrt_print_i32`
  (64-bit-safe sign handling, div-by-10 digit loop, one write syscall).
  Image remains ONE R+X PT_LOAD: headers | code | stubs | trap_exit |
  runtime | _start | rodata (ADR-008 decision 6; no RW segment yet —
  nothing needs it).
- IR extended additively (ADR-008 decision 5): IR_ADD/SUB/MUL/DIV/REM,
  IR_PRINT, IR_PRINT_STR, IR_JMP, IR_JMPZ; the two M1 opcodes are
  untouched; jump targets are instruction indices patched from labels.
- The M2 surface grammar is recorded as TEMPORARY (ADR-008 section 0;
  user rule: syntax is finalized last). The file extension question is
  in ADR-009 (PROPOSED; decision reserved to the user; `.k` naming kept
  temporarily, not enforced by the toolchain).

## Verification (what actually ran)

1. **Three-way conformance** (`tests/run_m2.py`): 40/40 checks green.
   Every case requires byte-exact equality of (stdout, stderr, exit)
   across ELF == interpreter == `tests/reference.py` (an independent
   Python implementation of the same ADR prose, never reading compiler
   output). Includes per-operator boundary matrix:
   add/sub/mul at both overflow edges, div/rem sign matrix
   (7/2, -7/2, 7/-2, -7/-2), 46340^2 (max square) vs 46341^2,
   INT32_MIN arithmetic, division by zero, INT32_MIN / -1,
   INT32_MIN % -1, traps mid-expression, stdout written BEFORE a trap,
   if/else nesting, exit code = return value & 0xFF, UTF-8 strings.
   Negative cases (10) check the specific diagnostic, its span, AND
   that no output file is created on failure.
2. **M1 regression**: `tests/run.sh` 16/16 (untouched suite).
3. **Differential fuzz** (`scripts/fuzz.py --mode diff`): 80,000
   generated inputs (nested arithmetic, boundary numerals, 10-40-digit
   strings, if/else nesting; seed 20261026): 48,014 accepted programs
   checked three-way against the oracle; 31,986 compile-rejected
   (lexer/checker rejection paths); 0 mismatches, 0 crashes, 138.5 s.
4. **Sanitizer fuzz** (`--mode asan`, gcc ASan+UBSan build): 20,000
   inputs (grammar-aware + fixture mutations; seed 424242) x build /
   interp / dump-ir = 60,000 execs; 0 sanitizer reports, 0 crashes,
   248.6 s, ~241 execs/s.
5. **libFuzzer (clang 19.1.7, ASan+UBSan, coverage-guided)**: harness
   covers lex -> parse -> check -> ir_build -> interp(quiet) -> emit
   in-process. Two 301 s sessions (seeds 1001, 777007; corpus carried
   over, seeded from 53 fixtures): 6,607,327 + 7,199,820 = 13,807,147
   execs, ~22-24k exec/s, corpus grew to 2,978 units, peak RSS ~350 MB;
   0 crashes, 0 sanitizer findings. Corpus NOT committed (regenerated
   per run).

Honest coverage limits (all runs): the differential mode uses the
plain -O2 build (memory-safety coverage comes from the ASan/libFuzzer
legs); the CLI arg-parsing and file-IO error paths are not fuzzed; no
persistent-process mode; no cross-run corpus; generated-code execution
is only exercised via the fixture suite (compiled programs are
trivially memory-safe by construction — no variables, no pointers);
the kernel syscall layer is not fuzzed. The oracle is a third
implementation and can itself be wrong; the runner saves any
disagreement for triage (none occurred).

## Small decisions taken and recorded (per user condition ز)

All in ADR-008: trap exit code 101; exact trap message bytes; no
constant folding in M2; truncation-toward-zero division; INT_MIN%-1
traps; print adds no newline; unary-minus literal rule; string escape
set (5 escapes, UTF-8 passthrough, 127-byte limit); capacity limits
(ADR-008 decision 7); no RW PT_LOAD yet; rodata inside the R+X segment
(W^X refinement deferred); per-site preformatted trap strings (limit
1024); only main is lowered (M1 rule kept); `else` requires a block;
`return` stays top-level-last only.

## Flagged to the user (stop-condition check, condition ز)

The IR was EXTENDED (8 new opcodes) to implement the mandated scope.
Judged ADDITIVE, not a one-way door: the two M1 opcodes keep their
encoding and semantics, the IR is an internal never-persisted format,
and M1 programs still compile identically. If the user considers any
part of this irreversible, M3 has not started and the decision can be
revisited before then.

## Known limitations (explicit)

- No comparison operators, no variables, no loops, no calls — by
  design (M2 scope); conditions are integer expressions.
- A program whose input path exceeds 200 bytes AND contains
  arithmetic is rejected at compile time (trap messages are baked
  into the binary).
- print ignores write() errors (documented in ADR-008).
- README.md and STATE.md were intentionally NOT touched (user
  decision 3, freeze until the private/public announcement); the
  pending README/STATE lines are listed in the M2 chat report.
