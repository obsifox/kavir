# Milestone M3 — Flow + calls (COMPLETE, 2026-10-26)

Status per the milestone ladder in ADR-005 v3, scope narrowed BY THE
USER (2026-10-26): comparison operators, while, let (local variable),
user function calls + recursion (fib) — nothing else
(loop/break/continue excluded). M1/M1.1/M2 stand as AUTHOR-APPROVED
(not independently verified); independent verification of 28ba9f1 is a
third-party task. M3 was built on top of local commits 8aa46cd + 4d0921b.

## What was built (scope: user-narrowed — nothing more)

- Comparisons `< <= > >= == !=` yielding i32 1/0, parsed as ONE level,
  non-associative (`a < b < c` is a clean compile error).
- `while (cond) { ... }` — condition re-evaluated per iteration;
  conditions are i32, nonzero = true. No loop/break/continue (user
  narrowed the scope).
- `let x: i32 = e;` (immutable) and `let mut x: i32 = e;` (mutable) —
  USER DECISION (ADR-010 gate), matching the ADR-005 v3 wording.
  Assignment `x = e;` is a statement, only to mutable locals;
  parameters are immutable; flat per-function scope, no shadowing;
  initializers mandatory and evaluated before the binding exists.
- User function calls with 0..8 arguments (ADR-010 capacity), forward
  references and mutual recursion (signatures collected first), early
  `return` anywhere (the M2 "return must be last" rule relaxed —
  err_return_in_if.k became the positive cases_m3/early_return_in_if.k),
  falling off the end returns 0 (M2 semantics, unchanged).
- ADR-010 ACCEPTED via the user gate: SysV AMD64 integer subset
  (RDI RSI RDX RCX R8 R9; args 7+ on the stack right-to-left; return
  in EAX), RBP frames, 16-byte call-site alignment, and the recursion
  depth limit **1024** (user choice) enforced IDENTICALLY in the ELF
  (hidden depth argument in R11D, checked in every prologue) and the
  interpreter (explicit frame-stack index) with byte-identical trap
  messages. All functions are emitted (M2 emitted only main).
- IR extended additively: +8 opcodes (LT LE GT GE EQ NE COPY CALL;
  args inlined in CALL). The IR remains internal, never persisted.
- The interpreter was rewritten to an EXPLICIT frame stack (no C
  recursion): frame index == Kavir call depth, mirroring the machine.

## Bugs found and fixed during bring-up (all caught by tests/fuzz)

1. `IR_RET` ended code generation: code after an early return was
   never emitted (M2 always had RET last) — forward jump targets
   resolved into the next function. Caught by the fib smoke test.
2. IR branch labels were GLOBAL (LBL_IR_BASE + inst index): generating
   the next function overwrote the previous function's label positions.
   Now per-function (LBL_IR_BASE + fn_idx*KAVIR_MAX_INSTS + k).
3. Variable vreg mapping used the name-table INDEX instead of the
   assigned vreg number — lets claimed vregs after expression
   temporaries, so reads read the wrong slots (fib printed garbage).
4. Ad-hoc div-skip labels were PER-FUNCTION: two functions with
   divisions collided when forward fixups were patched at the end.
   Now a global counter above the stub range.
5. Off-by-one in the ELF depth check (`cmp 1023/jae`) — killed the
   legal 1024th frame; the boundary fixtures
   (trap_depth_boundary_ok / trap_depth_limit) pin 1022 ok / 1023
   traps... precisely: count(1022) runs (1024 frames), count(1023)
   traps (frame 1024 would be the 1025th).
6. Oracle-only bugs (the independent reference implementation, not the
   compiler): early `return` inside if/while was swallowed by its own
   statement walker (infinite recursion on fib), and the depth check
   was off by one. The three-way contract caught both via hangs and
   mismatches.

Honest coverage limits: diff mode runs the plain -O2 build (memory
safety comes from the ASan leg; libFuzzer did not run here); CLI
arg-parsing and file-IO error paths are not fuzzed; generated while
loops are counter-terminated and generated calls form a DAG (no
unbounded recursion), so the depth trap is exercised by fixtures, not
fuzz; the oracle is a third implementation and can itself be wrong —
disagreements are saved and triaged (three oracle bugs were found and
fixed during bring-up, listed above).

### v0.1.0 scope review (amendment (a)) — coordinator opinion

KEEP the scope; do NOT shrink now. Reasons: the riskiest parts of the
ladder (custom backend, ELF, ABI, calls) are de-risked and byte-verified
against two independent executors; the calibration shows the estimate
holds with margin; M4 is the next real stress point (SysV struct
classification), and M5 is the genuine scope-risk milestone — the
m5cut contingency stays armed with its objective trigger. The first
scope conversation that matters is therefore AT M4's completion (when
aggregate cost is measurable), not now. One scope-shrink option worth
pre-deciding if M4 overruns: structs/enums by value with ≤8-byte
integer-only layouts first (defer the 16-byte two-register class to a
follow-up), which keeps Option[T] and match intact.
