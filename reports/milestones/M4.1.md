## 3. clang-only finding

With clang 18 the harness build flagged `ir.c:695: variable 'base'
set but not used` (gcc does not flag this shape). Audit showed `base`
was a leftover accumulator: params claim vregs sequentially via
`b.vreg += w` in the NEXT loop, so the sum is never consumed. Dead
store removed; behaviour covered by the full regression.

## 4. libFuzzer — RAN (first successful campaign)

Environment: the sandbox has no clang and no sudo (recorded in
M3/M4). M4.1 route that finally worked, WITHOUT root:
`apt-get download clang-18 libclang-cpp18 libllvm18
libclang-rt-18-dev libclang-common-18-dev` + `dpkg -x` into /tmp +
PATH/LD_LIBRARY_PATH. Debian clang 18.1.8.

Findings, in order:

1. **Campaign 1: libFuzzer TIMEOUT (real finding).** A coverage-
   guided mutation (ChangeASCIIInt) turned a bounded loop into a
   legal divergent program (`while (i < limit()) { ... i = i + 0; }`).
   The harness ran the IR interpreter with NO step budget, so the
   legal divergence hung the harness. Triage: `kavir build` on the
   same input exits 0 instantly — the compiler is unaffected;
   divergence is legal Kavir semantics (the compiled ELF would loop
   identically). **Harness limitation, not a soundness bug.** Input
   preserved as `fuzz-crash-timeout-m41-divergent-loop.k` (gitignored,
   kept for triage).
   Fix: optional interpreter step budget — `interp_set_step_limit()`
   + `InterpResult.step_limited` (harness-only; the CLI stays
   unlimited; the three-way contract is untouched) + `-timeout=10`
   added to the make target.
2. **Campaign 2: LSan exit check.** LeakSanitizer flags the
   pipeline's process-lifetime pools at exit. Measured: 1 x 256 KiB
   allocation at 2.5k execs; 41 allocations / 10.7 MiB at 407k execs;
   RSS flat (~144-157 MB) — bounded pools, NOT per-input growth
   (the harness deliberately reuses static Program/IrModule pools;
   see fuzz_frontend.c). The target now sets
   `ASAN_OPTIONS=detect_leaks=0` with the measurement recorded in
   the Makefile comment.
3. **OFFICIAL M4.1 campaign** (`make fuzz-libfuzzer`, corpus seeded
   from all fixtures):

       Done 389216 runs in 61 second(s)
       stat::number_of_executed_units: 389216
       stat::average_exec_per_sec:     6380
       stat::new_units_added:          682
       stat::slowest_unit_time_sec:    0
       stat::peak_rss_mb:              157

   0 crashes, 0 timeouts, 0 sanitizer findings. These numbers belong
   to M4.1's harness; they are NOT retroactively claimed for the
   M3/M4 reports.
