## 1. Bug 1 (SIGSEGV): sret pointer vs stack-parameter word

Symptom: a function that directly returns an aggregate parameter
larger than 2 words, with NO local variables, crashed the compiled
ELF (SIGSEGV).

Root cause (backend, `gen_function`): the frame's vreg area was
sized from DEST-writing instructions only (`nregs`), but PARAMETERS
also occupy vreg words. In the worst case (a body with zero
dest-writing instructions -- just `return x;`) the frame had no
parameter space at all: parameter stores aliased the depth slot and
the hidden sret-pointer save slot and spilled below the frame. The
disassembly of the crashing program shows it exactly:

    sub rsp,0x10                     ; 16-byte frame (nregs=0)
    mov [rbp-0x8],r11d               ; depth slot
    mov [rbp-0x10],rdi               ; sret pointer saved
    mov eax,[rbp+0x10]; mov [rbp-0x8],eax   ; param word0 -> -8
    mov eax,[rbp+0x14]; mov [rbp-0x10],eax  ; param word1 -> -16
    ...                                     ; (clobbers the sret ptr)

The epilogue then reloaded the CLOBBERED slot (`mov rdi,[rbp-0x10]`
yielded 22) and wrote 6 result words through it -- SIGSEGV.

Fix: `gen_function` pass 1b now also counts parameter words into
`nregs` (the interpreter was never affected: its frames are sized by
`fn->nvregs`, which already counts parameters -- the three-way
oracle agreed with the source semantics all along; only the ELF
diverged).

Permanent regression matrix (`scripts/gen_m42_matrix.py` ->
`tests/cases_m42/`, run by `tests/run_m42.py`, three-way
ELF == interpreter == reference.py):

- aggregate size 4, 8, 12, 16, 20, 24, 32 bytes (1, 2, 3, 4, 5, 6, 8
  words: one-register, packed-two-register, and stack/sret classes);
- callee locals 0, 1, 3;
- return kind: direct parameter return / locally-built result /
  chain through three calls;
- scalar context: none / 3 scalars (registers) / 3 before + 4 after
  the aggregate (registers AND stack units on both sides), plus a
  printed scalar-only call so the scalar mapping is observable.

Full cross product: 189 programs. All pass three-way (202/202 with
the nested-match cases below).

## 2. Bug 2 (nested match on user enums)

Symptom: a match nested inside another match's arm was checked
against the OUTER scrutinee (`pattern type 'B' does not match the
scrutinee type 'A'`).

Root cause (parser + checker + IR): match arms live in ONE
program-wide pool (`prog->arms[]`), and arm BODIES are parsed
between an arm's claim and the next arm, so a NESTED match appends
its arms INTO THE MIDDLE of the outer match's run. The checker and
the IR lowerer walked own arms as a contiguous run
(`arms[arm0 + i]`) and therefore read the nested match's arms.

Fix: `MatchArm.next_own` chains each match's own arms; `EX_MATCH.aux`
now stores the FIRST own arm and both consumers (check.c, ir.c) walk
the chain. The pool itself is now sized independently (see bug 3).

Permanent tests (`tests/cases_m42/`, run by `tests/run_m42.py`):
positives `m42_nested2.k` (2-level, all four paths + wildcard
variants), `m42_nested3.k` (3-level, all eight leaf paths),
`m42_nested_option.k` (Option inside enum arms and enum inside
Option.Some, both directions); negatives, each NESTED so the fix is
exercised:

| Shape | Diagnostic (regex) |
|---|---|
| S1 pattern/scrutinee type | `pattern type 'A' does not match the scrutinee type 'B'` |
| S2 duplicate variant | `duplicate pattern for variant 'B1'` |
| S3 non-exhaustive | `match is not exhaustive: variant 'B2'` |
| S4 variant arity | `variant 'B2' carries 2 value(s); the pattern binds 3` |
| S5 unknown variant | `enum 'B' has no variant 'B9'` |
| extra: wildcard placement | `'_' must be the last match arm` |
| extra: arm body type | `match arm bodies must be i32` |
| extra: Option.None scrutinee | `Option.None pattern requires an Option scrutinee` |
| extra: match on non-enum | `match requires an enum value` |
| extra: Option.Some arity | `Option.Some carries 1 value(s); the pattern binds 2` |

## 3. Bug 3 (arm cap counted program-wide) + capacity audit

Root cause (parser): the per-match arm limit was tested against
`prog->narms` -- the PROGRAM-WIDE pool total -- so after enough
arms accumulated anywhere, every later match was falsely rejected
(`too many match arms (limit 32 per match)` on a 5-arm match).

Fix: two distinct scopes with two distinct diagnostics:
`KAVIR_MAX_ARMS 32` per match (tested against `own_arms`), and the
new `KAVIR_MAX_ARMS_POOL 512` per program for the shared pool
(`too many match arms in the program (limit 512 total)`). The
bug-3 regression is pinned both by `err_`-free matrix programs with
many matches and by the capacity suite.

## 4. Bug 4 (NEW, found by the capacity suite): label one past the last IR instruction

`internal: unresolved label` on `if (t) { return 7; }` as the last
statement of a function: an else-less if places its else-label at
index ninsts (one past the last instruction, "fall off the end"),
and the backend never reaches that index to place the label, so the
jump fixup stayed dangling.

Fix: the backend now places a label interned at index `fn->ninsts`
at the fall-off epilogue (semantically exact: the label means "fall
off the end" and the epilogue returns zeroes); `place_label` in
ir.c rejects the only impossible corner (ninsts == KAVIR_MAX_INSTS,
which would index past the backend intern table) with a clean
diagnostic, and all seven call sites check it. Regression: the
capacity suite's nested-if emitters exercise this at depth 255;
explicit three-way checks of the minimal shapes pass.

## 5. Bug 5 (NEW, found by the new negative tests): Option.Some arity diagnostic had UB

The `Option.Some` arity error used a format string with TWO `%d`
conversions but only ONE argument -- undefined behaviour on that
error path (it printed garbage: `binds 708`). Fixed to
`Option.Some carries 1 value(s); the pattern binds %d`; the
`err_m42_x5` test pins the corrected text.

## 7. Root-cause analysis: why the repo tests and fuzz missed these bugs

All three bugs were SHAPE/SCALE gaps, not oracle gaps -- the
three-way contract (ELF == interpreter == reference.py) was never
the weakness; nothing exercised the shapes:

1. Bug 1: every M4 fixture called aggregate functions whose bodies
   wrote destinations (locals, sums), so `nregs` always covered the
   parameter words; the crashing shape (a body with ZERO
   dest-writing instructions returning an aggregate parameter
   directly) never appeared. The pre-M4.2 generator only produced
   aggregate->i32 helpers, never aggregate->aggregate identity
   returns. The interpreter agreed with the oracle on every existing
   case because its frames were sized correctly -- only the ELF
   diverged, and no case ran that ELF shape.
2. Bug 2: every match in the fixtures was flat and top-level; the
   arm-pool contiguity assumption only breaks when an arm BODY
   contains another match. Nesting is a state-shape dimension that
   no fixture or generated program visited.
3. Bug 3: the false rejection needs MORE THAN 32 arms across
   several matches in ONE program; fixtures and generated programs
   carried only a handful of matches each. Capacity scopes were
   never probed AT their limits -- hence the new boundary suite.

Meta-lesson: bug 2 even failed at COMPILE time with a wrong
diagnostic, i.e. the suite had no negative test asserting the
ABSENCE of spurious diagnostics. The new suites close the three
gap classes mechanically: a parameter-space matrix (bug 1), a
nesting suite (bug 2), and per-capacity boundary triplets (bug 3).
The new suites immediately bit twice more (bugs 4 and 5), which is
the intended effect.
