# Milestone M4 — Aggregates (COMPLETE, 2026-10-27)

Status per the ADR-005 v3 ladder: structs by value, enums as tagged
sums, match with exhaustiveness, Option[T] builtin — NOTHING ELSE
(user's instruction; ADR-004 cut list respected). Built on local
commit 1ae4dcd (M3.1). M4 is AUTHOR-APPROVED ONLY; no independent
verification is claimed.

## What was built

- Structs (value semantics): declaration-order literals, field
  chains, field assignment through `let mut` roots, whole-value
  assignment, copy-on-bind (aliasing unobservable), nested structs.
- Enums (tagged sums): i32 tag at word 0 = variant index, payload
  values from word 1; bare and payload-carrying constructors.
- match: exhaustiveness (every variant or final `_`), duplicate-
  pattern rejection, arm-local bindings that may not shadow outer
  variables, flat patterns only (ADR-004 cut list 1); arm bodies
  are i32 (the M4 deconstruction surface).
- Option[T]: builtin monomorphisation (`Option<T>` synthesized
  enums), T inferred from the expected type at ctor sites, Some
  payload type-checked; nested Option[Option[i32]] works.
- Aggregate ABI per ADR-011 (USER DECISIONS 2026-10-27): C layout;
  ≤8B values in ONE register (SysV eightbyte packing); >8B values
  ALWAYS memory — stack copy in 8-byte units for arguments,
  hidden-pointer return (RDI) with a caller scratch area; RAX = RDI
  on memory-class return. Documented deviation: 9..16B values use
  memory where psABI would use two registers.
- IR: aggregates lowered to CONSECUTIVE WORDS (one vreg per i32); NO
  new opcodes — construction/field access/match lower to the M3 core
  (CONST/COPY/EQ/JMPZ); IR_CALL carries per-argument and return word
  counts. Interpreter: word-wise CALL/RET with the same word counts.
- Three-way oracle (tests/reference.py) implements the FULL M4
  surface independently (aggregate values with copy semantics).

## Bugs found and fixed during M4 bring-up (all caught by the suites)

1. Postfix chains did not apply to call results (`mkpair(1,2).lo`).
2. Nested struct literals interleaved their field names in the
   shared literal pool (contiguous per-literal blocks now).
3. The 2-word register pack used RDX as scratch while RDX was
   argument 2 — R10 is now the pack scratch (caught by m4_mix_8args
   bit-weights).
4. Match arm SLOTS were claimed after body parse — a nested match
   inside an arm body appended its arms to the same pool and the
   outer match read the inner's arms (arm-slot-before-body fix).
5. Recursive types were accepted while forward references resolved
   as i32 during layout — the layout pass now runs after ALL
   annotations resolve (err_recursive_type.k).
6. Option.Some payload type was not compared against T
   (err_option_wrong_elem.k).
7. A mangled early draft of the arm-body check hid the check behind
   an `if` (found while debugging 4); the final code has the check
   unconditional.
